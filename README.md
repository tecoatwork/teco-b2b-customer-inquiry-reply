# B2B询盘分析和回复

一个用于分析B2B询盘、理解客户及联系人，并起草简短有效回复的 Skill。

核心思路：先理解客户为什么问、联系人为什么在意，再用 FABMP 组织价值，最终给出“价格范围 → 核心工艺差异 → 应用选项 CTA”的三段式回复。

## 设计者的五点思路

### 1. 分析客户公司、产品线与询盘动机

分析客户的公司和产品线，了解背景信息以及发询盘的动机。

研究客户卖什么、服务谁、现有产品如何定位，以及本次询盘产品与其业务的关系。结合询盘判断：客户可能是在扩充产品线、寻找替代供应商、解决质量问题、为具体项目选型，还是初步了解价格。

这些信息应影响回复中的适用场景、差异化卖点和下一步问题。已核实背景与动机推测分别呈现，不把“可能需要”当成“正在采购”。

### 2. 分析询盘人的职位与个人工作 Meaning

分析发询盘人的职位，思考他们个人工作所追求的 Meaning。

公司想得到的业务结果，与联系人希望在工作中实现的意义，需要分开理解。例如，公司可能希望降低质量成本；采购负责人可能希望自己的供应商选择有据可依，产品经理可能希望推动新品顺利上市，工程人员可能希望减少验证和返工负担。

Meaning 应基于实际角色、询盘内容和工作情境提出假设，并在后续沟通中校正。回复应体现对其工作的帮助，不直接揣测或点破个人心理。

### 3. 使用 FABMP 作为回复的核心思路

| 要素 | 含义 | 在询盘回复中的问题 |
| --- | --- | --- |
| F — Feature | 产品或服务特征 | 我们具体做了什么？ |
| A — Advantage | 相对优势 | 这项设计或工艺在什么条件下更有优势？ |
| B — Benefit | 客户公司的业务收益 | 它如何影响成本、质量、销售、交付或上市？ |
| M — Meaning | 联系人的工作意义 | 这个结果对他完成工作有什么帮助？ |
| P — Proof | 证据与验证 | 客户凭什么相信，如何核验？ |

内部先完成完整价值链，对外不机械罗列五个字母。每次只选择一个与当前询盘最相关的价值主题，将工艺、收益、角色意义与证据连起来。

### 4. 询盘回复采用三段式

#### 第一段：快速给答复，绝不墨迹

既然客户处于即时沟通中，就要立刻给客户一个价格范围，满足他希望快速得到答案的心理，同时用一句话明确适用场景。

不要先介绍公司历史、堆砌客套话，或用一串问题挡住报价。客户应首先知道“大致多少钱、对应什么产品和用途”。

#### 第二段：展示核心差异化

给出价格后，立刻抛出一个低价同行根本做不到或不愿提的核心工艺差异化，在客户心里建立对比锚点。

这一步的设计意图是让客户有能力比较价格背后的工艺和使用结果。执行时必须有依据：说明我方真实工艺、应用价值及验证方式；没有竞争对手证据时，不把“同行做不到”写成事实断言。优先揭示容易被忽略、却会影响使用或业务结果的比较条件。

#### 第三段：CTA，让客户轻松回复 A 或 B

不用问采购量——在这一阶段，客户往往还不愿意或无法提供。直接问最直观的商业应用选项，让他动动手指打个 A 或 B。

例如，在产品和客户背景适用时，可以问：“主要用于 A. 自有品牌零售，还是 B. 专业门店使用？”选项必须能帮助下一步推荐。如果客户已经说明用途，就问下一个必要的应用细分，不重复问已知信息，也不强行制造二选一。

### 5. 使用成熟理论优化回复

使用福格行为模型、社会心理学等理论，检查回复为什么值得回答、是否容易回答、下一步是否清楚。

福格行为模型强调行为发生需要动机（Motivation）、能力（Ability）和提示（Prompt）同时出现。本 Skill 将其用于回复设计：

- 动机：快速回应价格与场景，并说明与客户业务、联系人工作相关的价值。
- 能力：减少阅读与思考负担，让客户不必查表或内部开会就能回复。
- 提示：只给一个明确、轻量的 CTA，例如选择 A 或 B。

社会心理学方面，先提供有用信息，再提出轻量请求；通过具体比较条件辅助判断；有真实且相关的案例时才使用社会证明。不制造虚假稀缺、权威、口碑或焦虑。

理论用于指导设计，不保证回复或成交。FABMP在这里是价值表达框架，不宣称它是统一实验验证的心理学定律。具体理论效果需核对研究来源，实际效果需通过真实询盘反馈检验。

福格模型官方来源：[Fogg Behavior Model](https://www.behaviormodel.org/home)。

## 执行时的补充规则

- 报价必须来自我方有效资料，保留币种、单位、配置及必要条件；不能凭市场印象编造价格范围。
- 只有确定价格时就给确定价格；缺少价格时向使用者索取依据，草稿明确标注尚不可直接发送。
- 工艺、认证、性能、案例与交期必须有依据；拟进行的验证不能写成已完成的证据。
- 不混用不同品牌或相邻型号的产品事实。
- 三段式默认适用于即时询盘首回复；正式 RFQ、复杂技术选型和售后问题优先满足客户实际要求。
- 只研究和起草，不自动发送消息，也不自动修改客户记录。

## 使用方式

提供询盘原文，以及已有的客户公司或网站、联系人职位、我方产品资料、报价条件与工艺证据。信息不全也可以开始，Skill 会区分可完成部分与关键缺口。

```text
使用 $teco-b2b-customer-inquiry-reply 分析以下询盘并起草回复。

询盘原文：……
客户公司/网站及联系人：……
我方产品与报价依据：……
已验证工艺或证据：……
```

默认输出：简短客户与动机分析、角色及 Meaning 假设、一条 FABMP 价值链、客户语言的三段式回复，以及必要的缺项说明。只需要正文时，可以明确要求精简输出。
